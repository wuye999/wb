# 商品运营报告

`report products` 默认生成低评分VC、高退货率VC及近期出单筛选三类清单，附数据覆盖与异常说明。命令只读，使用现有本地快照和本轮 WB Open API 数据。

## 配置与使用

BCS 凭证用于读取账号店铺列表及各店的 WB 官方令牌。报告复用本地商品快照、中文名映射和已有提交记录，无需配置飞书或安装 `lark-cli`。旧参数 `--url` 和 `--table` 已移除。默认目标为本机 BCS 账号当前返回的店铺，`--shops` 仅缩小本机目标店范围。

```powershell
python run.py report products
python run.py report products --shops 1001,1002 --wb-region cn
python run.py report products --order-days 30 --feedback-days 365 --out exports/product_report.xlsx
python run.py report products --details
```

示例ID为占位。默认 `.ru` 官方主机；需要 `.cn` 时显式指定，不会自动跨主机或使用Cookie兜底。官方令牌需具备 Analytics、Feedbacks and Questions、Marketplace 类别权限。后台Cookie和BCS登录Token都不能替代官方令牌；令牌仅在内存使用，不写入工作簿或日志。

订单接口常规限额为每店每分钟一次，客户端每次请求至少间隔60秒；评价至少间隔0.35秒。以上针对个人、服务或带密钥基础令牌；低限额基础令牌可能不适用。429停止该阶段并报告未知，不等待数小时；401/403也不会启动浏览器或自动续期。翻页数量会影响运行时长。

### 临时引入其他BCS账号

需要扩大统计样本时，可提供其他账号在 `https://wb.bcserp.com/prod-api/` 下人工复制的完整fetch抓包。接收命令如下，调用方或AI须通过子进程标准输入管道传入UTF-8文本，传完关闭输入流；不在终端交互粘贴，不将凭证拼进命令行或保存到脚本、抓包文件。

```powershell
python run.py report products --extra-bcs-stdin
python run.py report products --shops 1001 --extra-bcs-stdin --wb-region cn
```

- 输入支持JSON形式的 `fetch("地址", {"headers": ...})`，多个完整fetch块依次排列，可带Markdown代码围栏；输入上限1MiB。请求头必须含 `Authorization: Bearer ...`、`X-Limit-Key` 和 `Cookie`，名称大小写不敏感；Cookie中已有的认证值必须与请求头一致，重复JSON字段会被拒绝。这里只解析认证，不执行JavaScript，也不重放原请求。
- 每个临时账号独立查询完整店铺列表及官方令牌，全部店铺用于补充退货、近 7/14 天有效出单、差评和链接指标。只有本机目标店需要本地快照和提交记录，也只有这些店铺进入「店铺链接缺口」。中文名复用本机映射，无法确认时保留未知。
- `--shops` 只筛本机目标。即使只选择一个本机店铺，也会采集临时账号的全部店铺。
- 选定来源按BCS店铺ID去重，本机优先，其次按临时账号输入顺序；同ID名称冲突时保留优先来源并报错，不重复计数、不自动切换凭证重试。
- 临时BCS凭证及读取到的官方令牌只留在本轮内存，不写入凭证配置、日志、报告或状态；每次需要时重新提供，不影响其他命令的账号。输出的报告会保留采集到的业务数据。
- 空输入、格式或认证字段错误会在联网前结束；账号认证或店铺采集失败时保留错误，其他来源继续，最后输出部分报告并返回1。无法读取某个账号店铺列表时，“数据覆盖说明”及退货、差评汇总会标注该账号店铺范围未知，即使其他店铺采集完整也不会将整轮标为完整。

## 统计口径

### 默认筛选与简洁展示

- 商品按VC中唯一最长的连续数字段归一；前缀和较短规格尾号不同仍按同一商品合并指标。并列且不同的最长数字段不猜测，记入异常。数字段仅用于归组，不能作为店铺nmID。
- **低评分VC**：按全部授权店铺的评价数量加权计算合并评分，评分≤3.5，且在本机目标店快照中存在非回收站商品。同一完整VC只显示一行，列中文名、评分、评价数及存在店铺，不列各店商品链接。
- **高退货率VC**：在 `--order-days` 窗口内合并同数字段订单，列出完单口径兼容退货率≥30%且本机目标店存在的商品。同一完整VC一行，列存在店铺及分子、分母。
- **近期出单筛选**：近 14 天有有效订单，排除上述全部授权范围内的已知低评分或高退货率商品，中文名须唯一、精确匹配当前商品价格表。每个出单完整 VC 一行，列近 7/14 天有效出单件数、来源店铺及其 ID 和 nmID、已存在店铺、缺少店铺及待确认店铺。
- 本轮从本地库读取完整 VC 归属与价格表商品名。匹配多个不同商品名时保留核对线索。已排除或待认领商品仍按实况统计。
- 缺口按同数字段核对本机目标店的最新本地在架快照，已有其他前缀VC也算存在。缺快照、快照不完整、回收站已有或已有提交待确认的店铺单独列“待确认”，不直接建议重复建卡。缺口始终是本地快照证据，不代表实时平台状态。
- 无评价或完单分母为0时不命中已知风险阈值，可以出现在近期候选中，但必须标注评分/退货率未知；账号或店铺采集不完整也保留说明。筛选不修改原始数据。
- `--details` 追加下述原始汇总、订单、评价和链接证据表，按完整 VC 及商品链接追溯来源。

### 订单和评价统计

- 日期统一为 UTC+8，近 N 天含今天。订单明细保留近 `max(order_days, 14)` 天下单的业务仓订单。退货汇总、链接退货指标和高退货率筛选均只使用 `--order-days` 指定的下单窗口，范围 1–31 天，默认 30 天。
- **有效出单口径 A**只计在途（`created`）和已买断（`buyout`），排除取消、退货、瑕疵退货和未知状态。每条订单行计一件，按完整 VC 跨店分别统计近 7 天和近 14 天。缺 VC 的订单保留在订单明细，参与窗口内的退货统计，并跳过候选匹配。
- 订单动态接口按当前状态时间过滤，先取得状态时间超集，再按下单时间本地筛选。订单一行代表一件商品，不按平台订单号合并。官方在末页可能返回空 `snapshotTime`；仅不足请求页大小且游标明确为空时接受为末页，满页无游标仍报不完整。
- 只计按 `wb.warehouse_keyword` 在各店仓库目录唯一确认的本店业务仓，使用仓库目录的 `id`。订单动态通过同店 FBS 订单 `rid=srid` 关联，以其 `warehouseId` 核对业务仓。FBS 订单按不超过 28 天的分段读取并在重叠边界去重。缺少可验证仓库 ID 的订单被排除，报告标为不完整。
- **兼容退货率**＝（取消＋退货＋瑕疵退货）÷统计窗口内全部商品件数，分母包含在途和买断。**完单口径兼容退货率**分母为商品件数－在途件数。另列取消率及（退货＋瑕疵退货）÷统计窗口内全部商品件数。
- 未知状态计入商品件数并单列，不猜测其含义；存在未知状态时需人工核对兼容分母。未完结订单日后可能变更状态，当前比例不是最终结果。
- 中文名汇总用总数量计算比例，不平均各VC的百分比。完整VC跨店汇总；店铺＋商品码区分具体链接。订单动态缺少VC字段，报告优先使用同店FBS订单的 `article`。缺失时按商品码查同店快照，评价仅补充快照中未出现的商品码。所用来源内同一商品码有多个VC时，仅跳过该商品码的兜底映射并记警告。仍缺少VC的订单保留为未知并记错误，禁止从VC尾号猜码。
- 差评为1–2星。未处理、已处理及归档完整分页读取后按评价ID去重；`--feedback-days 0`（默认）表示接口可访问的全部历史。归档接口不支持日期参数，仍需完整读取后本地筛选。追加评价关系保留，按不同评价ID记录。
- 评价均分是所取评价的算术平均，不是前台合并商品卡评分。评价可取范围、可见性、合并卡或追加评价行为可能使数量不同于商品页展示，报告不声称代表前台所有当前可见差评。

## 工作表与缺失数据

默认工作簿前置低评分VC、高退货率VC、近期出单筛选，随后是数据覆盖说明、店铺数据覆盖和异常与缺失。`--details` 另外包含中文名退货汇总、VC退货汇总、VC差评汇总、店铺链接指标、差评明细、近7及14天出单、店铺链接缺口及订单明细。VC 差评汇总包含没有近期订单的已取评价商品。「近7及14天出单」保留符合口径 A 的完整 VC 汇总，供核对；「店铺链接缺口」对照本机目标店的快照逐个核对完整 VC。三张出单相关工作表均可通过「订单明细」追溯来源。

本地覆盖区分：快照中已存在、快照中未见、已有提交记录待生效或待确认、缺少快照无法判断；快照中有回收站卡时单独提示人工判断。均附快照或提交时间，不代表实时平台状态。命令不为补全结果擅自同步或更新快照。

“店铺数据覆盖”列出账号来源（本机账号、临时账号1等）和店铺用途；临时店铺的快照状态为“不适用：仅补充统计”，不因此判定失败。订单与评价汇总包含所有已选择、已授权的来源，“店铺链接缺口”只包含本机目标店铺。

空白数值代表未知或分母为零。采集不完整时，有效出单件数和其他统计值仅表示已知部分。分页上限、重复页、缺少响应字段、认证失败、无法确定唯一业务仓、快照损坏等问题会记录在报告中。其他独立来源继续采集，报告有错误时退出码为 1。

JSON 回执的 `data.period.orders_from` 是退货统计起点，`data.period.orders_collected_from` 是订单实际采集起点，`sales_7_from` 和 `sales_14_from` 是有效出单起点，终点均为 `through`。订单覆盖见 `data.orders_complete`，工作簿路径见 `data.artifacts.workbook`。

默认输出 `exports/商品运营报告_时间.xlsx`。它是用户商业数据，不应提交Git。仓库及人工凭证维护约束继续遵守 [配置](CONFIGURATION.md) 和 [AI指南](AI_GUIDE.md)。

## 官方接口

独立只读客户端仅允许以下接口，不包含商品写入方法：

| 类别 | 接口 | 用途 |
| --- | --- | --- |
| Analytics | `POST /api/analytics/v1/order-feed` | 订单状态超集，固定snapshotTime翻页；空页或明确空游标的短末页结束 |
| Marketplace | `GET /api/v3/orders` | 完整读取FBS订单，以rid核对订单动态srid的仓库ID和VC |
| Feedbacks and Questions | `GET /api/v1/feedbacks` | 分别读取未处理及已处理评价 |
| Feedbacks and Questions | `GET /api/v1/feedbacks/archive` | 归档评价，日期在本地过滤 |
| Marketplace | `GET /api/v3/warehouses` | 确认每店的业务仓名称和 ID |

完整字段以 [官方订单文档](https://dev.wildberries.cn/docs/openapi/analytics)、[官方评价文档](https://dev.wildberries.cn/docs/openapi/customer-communication)、[官方仓库文档](https://dev.wildberries.cn/docs/openapi/item-management) 为准。运行本命令不需要维护者的私有 `api/` 目录或HAR文件。
