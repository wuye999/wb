# 商品运营报告

`product-report` 将商品中文名和完整VC的退货指标、各店具体链接的差评、飞书近期出单以及本地店铺链接缺口汇总为Excel。报告保留所有候选，是否修改、下架、重新上架均由用户判断；命令没有 `--apply`，不修改平台或飞书，不触发BCS同步、fetch、merge或任务注册。

## 配置与使用

复用项目根目录 `data/`，无需更改既有凭证格式：BCS凭证用于读取账号店铺列表及每店 `apiKey`；飞书通过已登录的lark-cli读取 `feishu.base_url` 指定的「订单登记」表。准备本地商品快照、中文名映射及已有提交记录。默认目标为BCS账号当前返回的店铺；`--shops` 仅缩小目标店，不过滤飞书来源店铺。

```powershell
python run.py product-report
python run.py product-report --shops 1001,1002 --wb-region cn
python run.py product-report --order-days 30 --feedback-days 365 --out data/logs/product_report.xlsx
```

示例ID为占位。默认 `.ru` 官方主机；需要 `.cn` 时显式指定，不会自动跨主机或使用Cookie兜底。官方令牌需具备 Analytics、Feedbacks and Questions、Marketplace 类别权限。后台Cookie和BCS登录Token都不能替代官方令牌；令牌仅在内存使用，不写入工作簿或日志。

订单接口常规限额为每店每分钟一次，客户端每次请求至少间隔60秒；评价至少间隔0.35秒。以上针对个人、服务或带密钥基础令牌；低限额基础令牌可能不适用。429停止该阶段并报告未知，不等待数小时；401/403也不会启动浏览器或自动续期。翻页数量会影响运行时长。

## 统计口径

- 日期统一为UTC+8，近N天含今天。默认下单窗口30天，`--order-days` 范围1–31；出单同时列近7天与14天。
- 订单动态接口按当前状态时间过滤，先取得状态时间超集，再按下单时间本地筛选。订单一行代表一件商品，不按平台订单号合并。官方在末页可能返回空 `snapshotTime`；仅不足请求页大小且游标明确为空时接受为末页，满页无游标仍报不完整。
- 只计各店已确认唯一可用的莫斯科卖家仓，取仓库目录的 `id`。订单动态的物理仓名称可能不同于卖家自定义名称，因此通过同店FBS订单 `rid=srid` 关联，以其 `warehouseId` 核对已确认的仓库 `id`，不按地区名猜测、不使用office标识、不跨店关联。FBS订单按不超过28天的分段读取并在重叠边界去重；缺少可验证仓库ID的订单不计入，明确报告不完整。
- **兼容退货率**＝（取消＋退货＋瑕疵退货）÷商品件数；**完单口径兼容退货率**分母为商品件数－未完结，保留原报表定义。另列取消率、退货数、瑕疵退货数及（退货＋瑕疵退货）÷商品件数。后者不是已售商品的售后退货率。
- 未知状态计入商品件数并单列，不猜测其含义；存在未知状态时需人工核对兼容分母。未完结订单日后可能变更状态，当前比例不是最终结果。
- 中文名汇总用总数量计算比例，不平均各VC的百分比。完整VC跨店汇总；店铺＋商品码区分具体链接。订单动态不含VC，优先使用同店FBS订单的 `article`，缺失时使用同店快照和评价中的商品码映射，仍缺少时保留未知，不从VC尾号猜码。
- 差评为1–2星。未处理、已处理及归档完整分页读取后按评价ID去重；`--feedback-days 0`（默认）表示接口可访问的全部历史。归档接口不支持日期参数，仍需完整读取后本地筛选。追加评价关系保留，按不同评价ID记录。
- 评价均分是所取评价的算术平均，不是前台合并商品卡评分。评价可取范围、可见性、合并卡或追加评价行为可能使数量不同于商品页展示，报告不声称代表前台所有当前可见差评。
- 飞书一条登记记录计一单，`订单量` 求和为件数，延续现有统计口径；不按订单编号自动删除登记记录。保留来源VC、店铺、商品链接；兼容普通网址、富文本和CLI展示的Markdown超链接，并保留登记原文。登记链接不等于该店当前在售。
- 只有记录ID或辅助公式列「商品（链接）」、没有任何订单业务信息的占位行不计为订单，并列出警告；有VC、店铺或其他业务内容却缺日期的记录仍报错，不静默忽略。

## 工作表与缺失数据

工作簿包含数据覆盖说明、店铺数据覆盖、中文名退货汇总、VC退货汇总、VC差评汇总、店铺链接指标、差评明细、近7及14天出单、飞书出单明细、店铺链接缺口、订单明细、异常与缺失。VC差评汇总包含没有近期订单的已取评价商品；飞书明细保留每条来源链接，便于点击核对。外部店铺有出单记录但没有授权数据时，其风险为未知；不把本地其他店同VC的差评当作该外部链接的确切差评数。

本地覆盖区分：快照中已存在、快照中未见、已有提交记录待生效或待确认、缺少快照无法判断；快照中有回收站卡时单独提示人工判断。均附快照或提交时间，不代表实时平台状态。命令不为补全结果擅自同步或更新快照。

空白数值代表未知或分母为零。仅完整采集且未发现时才可解释为零；部分数据的数字是已知部分。分页上限、重复页、缺少响应字段、认证失败、无唯一莫斯科仓、快照损坏或飞书数据异常都会保留错误，不冒充空清单。不同店及独立数据源可继续采集；完成后输出报告，任何错误使退出码为1。

默认输出 `data/logs/商品运营报告_时间.xlsx`。它是用户商业数据，不应提交Git。仓库及人工凭证维护约束继续遵守 [配置](CONFIGURATION.md) 和 [AI指南](AI_GUIDE.md)。

## 官方接口

独立只读客户端仅允许以下接口，不包含商品写入方法：

| 类别 | 接口 | 用途 |
| --- | --- | --- |
| Analytics | `POST /api/analytics/v1/order-feed` | 订单状态超集，固定snapshotTime翻页；空页或明确空游标的短末页结束 |
| Marketplace | `GET /api/v3/orders` | 完整读取FBS订单，以rid核对订单动态srid的仓库ID和VC |
| Feedbacks and Questions | `GET /api/v1/feedbacks` | 分别读取未处理及已处理评价 |
| Feedbacks and Questions | `GET /api/v1/feedbacks/archive` | 归档评价，日期在本地过滤 |
| Marketplace | `GET /api/v3/warehouses` | 确认每店自己的莫斯科仓库名称和ID |

完整字段以 [官方订单文档](https://dev.wildberries.cn/docs/openapi/analytics)、[官方评价文档](https://dev.wildberries.cn/docs/openapi/customer-communication)、[官方仓库文档](https://dev.wildberries.cn/docs/openapi/item-management) 为准。运行本命令不需要维护者的私有 `api/` 目录或HAR文件。
