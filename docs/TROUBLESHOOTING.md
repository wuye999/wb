# 故障排查

先记录使用的解释器、命令、店铺范围、失败阶段和终端打印的结果文件路径。不要为了诊断刚提交的 WB/BCS 写入自动补跑同步或查询；先读取本次返回和本地日志。向维护者反馈时脱敏凭证与业务明细。

## 启动与路径

| 现象 | 处理 |
| --- | --- |
| 找不到 requests/openpyxl | 用运行脚本的同一解释器执行 `python -m pip install -e .`；确认没有把依赖装进另一个 Python |
| `No module named sellerops` | 在项目目录用 `python run.py --help`，或先 editable 安装；不要直接运行包内单个 py 文件 |
| 读取了其他数据目录 | 检查命令 --data-dir 和 SELLEROPS_DATA_DIR 环境变量，再确认 run.py 所在项目目录 |
| `unrecognized arguments` | 看对应 --help 和 CLI 参考；写命令不提供 --sync/--verify/--no-verify 参数 |
| 文件找不到 | 命令中的相对输入/输出文件路径通常相对当前工作目录；默认 data 根目录则由项目路径确定。这两者不同 |
| 参数解析退出码 2 | 检查必填项、选项拼写、互斥参数和取值；如 clean 必须给 --target，--data-dir 必须在子命令之前 |

## 凭证与外部工具

| 现象 | 处理 |
| --- | --- |
| BCS 401 / 网关错误 | 核对自己 data/credentials.json 的 bcs.token、limit_key、cookie_extra，不更换源码中的请求逻辑来试 |
| WB 店铺不在可用列表 | shopId 应是整数；authorizev3、wb_seller_lk、cookie 三项都要非空且属于同一店 |
| WB 后台 401/403 | 停止该店操作，人工登录并抓取一店会话，按 [手动抓包说明](CONFIGURATION.md#手动抓包更新凭证当前方式) 运行 `cookies-update` |
| 受限浏览器只有 Console / Elements，看不到 Network | 按配置文档运行定位用的失败 GET，再点击红色请求进入 Network；刷新页面后抓真实 API 请求，定位请求本身不作为凭证来源 |
| cookies-update 抓包无效 / 店铺 UUID 缺失或冲突 | 检查单个 fetch 块的 `authorizev3` 和完整 Cookie。按报错店铺 ID 核对登记的 `x-supplier-id-external`、已有 `Z-Sid` 和所属账号 |
| cookies-update 抓包文件找不到 | 相对文件名从 data/har/ 读取，使用 `session.md` 或绝对路径，避免重复拼入 data/har/ |
| cookies-update 签发或只读探针失败 | 整轮保留旧凭证。全店会话失效时重新抓包，单店失败时按报错 ID 核对店铺 UUID 和登录账号权限；限流或网络故障恢复后可重试 |
| 马帮缺少 www_cookie/shop_map | 按 CONFIGURATION 准备真实字段；shop_map 键须与马帮订单中的店铺文本一致 |
| 马帮要求腾讯验证码或短信验证 | 人工登录并进入上传预报单页面，按 [马帮配置](CONFIGURATION.md#马帮mabang) 导入成功 HAR；认证失败前已有的业务提交应先核对状态 |
| 马帮 NO_SKU / 匹配失败 | 查看本次报表，核对中文归属及价格表库存SKU；更换失败单不得直接推进预报/交运 |
| lark-cli 未找到 | 配置 PATH 或 SELLEROPS_LARK_CLI，确认对应工具支持 base 子命令和用户身份 |
| 飞书链接/表不存在、无权限 | 核对 base_url、--table、用户登录态和表权限；项目不会自动创建整份业务表 |
| 飞书分页报无 next_offset/没有前进 | 中止为避免漏读和重复登记；交维护者检查 CLI 输出/版本，不绕过去重改成只读第一页 |
| LLM 401/端点错误或生成失败 | 核对 key、model、完整 chat/completions 请求地址；ai-test 用本地样例但仍联网，不能用它冒充离线检查 |

## 数据与业务结果

| 现象 | 处理 |
| --- | --- |
| 商品价格表缺列 | 保留 Sheet1 和要求的表头；实际售价不能用旧名双倍售价代替，补齐字段后重试预览 |
| 公式无法解析/无缓存 | 用 Excel 等表格软件重算并保存，或明确填写有效售价；不把空价补零提交 |
| Excel PermissionError | 关闭占用目标表的 Excel/预览程序，保留备份，重试原本地操作；不用删除映射表解决 |
| JSON 损坏 | 从自己的备份恢复或交维护者定位；不要清空 state。跨进程锁文件长期存在是正常现象 |
| fetch 部分店铺失败、退出码非零 | 查 data/state/多店铺同步状态.json 的 errors；成功店铺已更新，失败店铺仍保留原快照。处理错误并重新成功拉取前，不继续 merge；已在后台同步时仍用 fetch --no-sync |
| BCS 商品重复、快照或单店表行数偏大 | 新读取会对同店相同 nmId/完整 VC 的兼容记录去重，保留完整原行；旧文件不会因升级自动改写。非空业务字段冲突、标识歧义或没有完整原行时会报错，不随意保留第一/最后一行。规则见 [数据契约](DATA.md#映射快照与标识)；整理旧文件前先备份 |
| 空店铺合并后单店表变空 | 有效空快照应清除该店旧商品明细和总表中的该店覆盖，历史归属池仍保留；不要用旧单店表恢复已经移除的在架记录 |
| merge 报快照缺失或损坏 | 缺失/损坏不等于空店铺，合并会中止；完成正确拉取或从备份恢复，不能创建空 JSON 绕过 |
| 筛选结果为空/全部跳过 | 核对 --shops、VC/中文名、映射表和已有快照；先解释缺哪项，不自动 fetch 或扩大到全店 |
| 找不到莫斯科仓 / 计划出现其他仓库ID | 中止该店操作，核对仓库名称及响应 id；当前只允许莫斯科，不回退其他俄语地区仓或成都，不用 office 字段 warehouseId 替代 |
| stock/trash 提示计划不完整、预览非零退出 | 查看被阻止的店铺和供应商代码；缺少唯一可用莫斯科仓、商品 ID 或任一规格 ID 时阻止对应操作。核对现有本地快照；需要更新时按用户要求独立 fetch/merge，不自动全量联网补查 |
| trash 清库存失败后没有移回收站 | 这是清库存前提：任何规格失败或回执不完整都会阻止整件商品下架，其他正常商品可继续。按日志处理具体失败项，不把已受理部分整批重放，不换 BCS 通道重放 |
| 想用 warehouse-clear 清库存 | 该命令针对成都仓永久删除，当前仅操作莫斯科的约定下不使用；不要把它当成普通库存清零 |
| 提交后本地显示旧价格/库存 | 这是快照未更新与平台异步处理的可能结果。读取本次日志后结束，不触发写后验证 |
| 超时但可能已被接受 | 保留任务号和本次结果，汇报未知/部分完成；不立即重放整批，不自动换通道再提交 |
| 订单统计日期与本机不一致 | 检查 order-stats 默认 America/Los_Angeles 时区、日期窗口、创建/更新时间口径 |
| 飞书登记出现重复 | 普通登记只追加去重后的新增；存量清理用单独的 feishu-register-dedup 预览，确认后再执行 |
| 库存表历史列不见了 | 检查是否执行过全量库存重建或显式日期区间模式，先用自己的表备份恢复，不再次重建覆盖 |

## 每日任务与退出码

daily/schedule 默认只是预览。实际执行 daily 加 --apply，注册 schedule 加 --apply；计划任务使用注册时记录的解释器和绝对路径，移动项目后需重新注册。内置任务按电脑本地时间运行，默认全部可用店铺；检查是否已有重复业务任务，避免重复提交。

daily 的某一步非零退出会停止后续步骤，先查看 `data/logs/daily_日期.log`。普通命令遇到失败也可能已有部分成功提交，非零退出不能作为整批重试的依据。

监听命令使用 --once 时，本轮读取、生成或发送失败会非零退出；持续监听则记录轮次异常后继续下一轮。查看本次日志和 CSV 区分已提交、失败、跳过及人工待处理项。退出码 0 不代表快照是最新值或平台已最终生效。各功能所需依赖见 [配置](CONFIGURATION.md)。

CLI 参数错误通常为 2，未捕获业务异常由主入口转为 1，中断为 130；具体处理器可返回自己的状态。不要因中断就断言远端请求未发生，按最后已提交步骤汇报。
