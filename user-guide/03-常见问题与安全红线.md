# 常见问题与安全红线

## 必须守住的 5 条安全红线

1. **先看计划单，再确认。** 改价、折扣、库存、下架、上架，先核对店铺、商品、规格和目标值。只确认本次看到的单号。范围不清或有受阻项，先请 WorkBuddy 解释。
2. **仓库只认本店已核实的莫斯科仓。** 每家店独立核对，找不到或匹配出多个仓时停止该店操作。下架要等全部规格清零受理。
3. **报错或超时先看回执。** 记录单号、已受理、失败和结果未知的项目。提交中或结果未知的请求禁止重发，整批也不要盲目重跑。
4. **平台受理后还需要处理时间。** 后台没立刻变化时，按本次回执判断进度。等平台处理，切勿因页面仍显示旧值就反复提交。
5. **私有资料留在本机。** 严禁外发或上传 `data/` 里的密码、价格表和登录资料，也不要贴到聊天、截图或 GitHub。

## 常见情况人话对照表

| 现象 | 怎么办 |
| --- | --- |
| 平台登录失效，或弹出登录验证 | 先停受影响的店铺。有过提交的，先保留并核对本次回执。再对 WorkBuddy 说「连接 WB」「连接 BCS」或「连接马帮」，在平台官网完成验证，按提示关窗后等连接结果。 |
| Excel 被占用，无法读取或导出 | 保存并关闭提示中的 Excel 文件和预览窗口，再请 WorkBuddy 重做原来的本地读取、导出或预览。 |
| 价格表缺列，或公式算出的价格没读到 | 在 `Sheet1` 第 1 行核对表头，补回「产品中文名」「最低售价」等所需列。公式先在 Excel 里重新计算，确认结果后保存再预览。售价空白先核实，不能当作 0。 |
| 筛不到商品，或有商品被跳过 | 让 WorkBuddy 给出完整跳过明细。核对店铺、完整中文名或卖家 SKU、商品归属和资料更新时间。有同名项时按完整商品编码核对。确实要查更宽的范围时说「名称包含」，资料太旧时单独要求同步。 |
| 发货提示缺 SKU，或发货方式为空 | 先核对这个订单对应的价格表商品，再把「发货方式」补为「马帮发货」「WB发货」或「不处理」。选马帮发货时填「马帮库存SKU」。保存后重新预览受影响且尚未提交的订单。 |
| 提交后线上没有立刻变化 | 看本次回执有没有平台受理记录、失败或结果未知。已受理就保留单号并等平台处理。结果不明时把原回执交维护者核对。 |
| 找不到导出的表格或 PDF | 请 WorkBuddy 给出本次导出的完整路径。表格默认在 `exports/`，WB 发货 PDF 在 `exports/fbs_shipments/` 的供货创建日文件夹。配送已受理却只缺 PDF 时，按原供货单补取。 |
| 需要把问题发给维护者 | 提供出错时间、你对 WorkBuddy 说的话、出错步骤、计划单号或平台任务号，以及脱敏的错误片段和受理、失败、跳过数量。写清是否已经提交过。用 A 店、旅行杯等代称遮住真实店名、商品、订单和买家信息。 |

可返回[快速上手](01-快速上手.md)或[日常功能速查](02-日常功能速查.md)核对操作步骤。
